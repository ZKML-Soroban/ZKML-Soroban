zkml-soroban is a runtime for executing small machine learning models off-chain
and verifying the correctness of their inference on Stellar through a Soroban
smart contract.

It builds on the zero-knowledge host functions introduced in Stellar Protocol 25
(X-Ray): BN254 elliptic curve operations ([CAP-0074](https://stellar.org/protocol/cap-0074))
for Groth16 pairing checks, and Poseidon hashing ([CAP-0075](https://stellar.org/protocol/cap-0075))
for model and input commitments.

<Note>
  The project is in active development (Phase 1). The off-chain pipeline and the
  on-chain Groth16 verifier are implemented; STARK-to-Groth16 proof compression,
  verification key export, and the testnet demo are still pending. See
  [Known limitations](/security/known-limitations).
</Note>

## How it works

<Frame>
  <img src="/diagrams/01-system-architecture.svg" alt="zkml-soroban system architecture" />
</Frame>


<Steps>
  <Step title="Commit to a model">
    Quantize a trained model to fixed-point and register its Poseidon commitment
    on-chain with `initialize`.
  </Step>
  <Step title="Prove an inference">
    Run the model on private input features inside the RISC Zero zkVM. The
    journal commits the model hash, input hash, raw output, and class label.
  </Step>
  <Step title="Verify on Stellar">
    Submit the Groth16 proof and the 80-byte public inputs to
    `verify_inference`. The contract runs the BN254 pairing check, blocks
    replays with a nullifier, records the result, and emits a `verified` event.
  </Step>
</Steps>

## Supported models

| Model               | Import            | Decision (`class_label`)       |
| ------------------- | ----------------- | ------------------------------ |
| Decision tree       | JSON, ONNX        | Always `0` (leaf value in `output`) |
| Logistic regression | JSON, ONNX        | `1` if score >= threshold, else `0` |
| Tiny MLP (ReLU)     | JSON, ONNX        | `argmax` of the output logits  |
