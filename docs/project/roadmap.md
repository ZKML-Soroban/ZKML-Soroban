## Phase 1: MVP

**Objective:** verify a decision tree KYC risk score on Stellar testnet with a
proof generated by the RISC Zero zkVM.

| ID   | Milestone                     | Deliverable                                                   | Status      |
| ---- | ----------------------------- | ------------------------------------------------------------- | ----------- |
| 1.1  | Project scaffold              | Workspace, crates, CI (fmt, clippy, tests, no_std, WASM, zkVM, docs) | Done |
| 1.2  | Fixed-point library           | Q16.16 checked arithmetic, activations, property tests       | Done        |
| 1.3  | Model representations         | Decision tree, logistic regression, tiny MLP, validation      | Done        |
| 1.4  | ONNX import                   | Tree, linear classifier, and MLP extraction with opset checks | Done        |
| 1.5  | Inference engine              | Shared engine, decision layer (`class_label`), batch APIs     | Done        |
| 1.6  | RISC Zero integration         | Guest program, receipts, differential tests (dev mode)        | Done        |
| 1.7  | Groth16 proof wrapping        | STARK to Groth16, VK export, real `VerificationBundleV2`      | Done (x86_64 Linux with Docker) |
| 1.8  | Verifier contract             | BN254 Groth16 check, RISC Zero receipt verification, model commitment check, admin, pause, nullifiers, TTL, events, budget tests | Done |
| 1.9  | Testnet deployment            | Deploy verifier and run the KYC demo end to end               | In progress (scripts and runner pending) |
| 1.10 | Documentation                 | Mintlify docs site, references, guides                        | Done        |
| 1.11 | crates.io release             | Publish `zkml-common` and `zkml-verifier` from `0.0.1`        | In progress |

### Remaining Phase 1 work

1. Deploy the verifier to testnet and verify a real receipt in a real
   transaction. The contract side is done (`verify_receipt`, issue #84) and
   costs 30.7M of the 100M instructions a transaction allows, but nothing has
   been deployed yet.
2. Add a remote proving backend (Boundless or a self-hosted Bento), since
   Bonsai was shut down in December 2025 and local compression needs x86_64
   Linux with Docker.
3. Fix the KYC demo: ONNX opset, `stellar` CLI deployment, demo runner.
4. Unify commitments on the domain-separated functions.

### Success criteria

- A decision tree trained on the synthetic KYC dataset produces an inference
  off-chain.
- A Groth16 proof of that inference verifies on Stellar testnet.
- End-to-end latency (proof + submission + verification) under 60 seconds.
- Proof size under 500 bytes.

## Phase 2: Native circuits

**Objective:** replace the generic zkVM with model-specific BN254 circuits for
smaller proofs, faster proving, and cheaper verification.

| ID  | Milestone                   | Deliverable                                            | Status      |
| --- | --------------------------- | ------------------------------------------------------ | ----------- |
| 2.1 | Decision tree circuit       | Native BN254 circuit for tree traversal                | Not started |
| 2.2 | Logistic regression circuit | Fixed-point linear algebra circuit                     | Not started |
| 2.3 | Tiny MLP circuit            | Dense layers with quantized ReLU                       | Not started |
| 2.4 | On-chain Poseidon           | Use CAP-0075 host functions where recomputation is useful | Not started |
| 2.5 | Benchmark suite             | Route A vs Route B: proof size, CPU instructions, latency | Not started |
| 2.6 | Verifier contract v2        | Multi-model registry, both proof routes                | Not started |
| 2.7 | Recursive proofs            | Evaluate Nova-style folding for batched inferences     | Not started |

### Success criteria

- Native proofs at least 10x cheaper to generate than Route A for decision trees.
- On-chain verification cost reduced by at least 50% versus Phase 1.
- Functional circuits with test vectors for all three model families.

## Risks

| Risk                                   | Mitigation                                        |
| -------------------------------------- | ------------------------------------------------- |
| RISC Zero API changes                  | Exact version pins, adapter layer                 |
| Hosted proving services shutting down  | Backend abstraction; Bonsai already replaced by Boundless |
| RISC Zero public input format vs contract | Dedicated Route A entry point, `verify_receipt` (done) |
| BN254 host function limits             | Early testnet measurement, budget regression test |
| Proving latency too high               | Boundless or GPU provers, Route B circuits        |
| Quantization accuracy loss             | `validate` accuracy pass against float outputs    |
| Contract size limits                   | Size-optimized `contract` profile, minimal logic  |
| Circuit audit requirements             | Third-party audit before mainnet                  |
| Quantum computers break BN254 Groth16  | Crypto-agile verifier and post-quantum track      |
